이번 프로젝트는 Docker 명령어를 직접 입력하지 않고 웹 화면에서 이미지와 컨테이너를 관리할 수 있도록 만드는 프로젝트입니다. 이번 주에는 기존 화면 초안을 실제 Docker Engine과 연결하는 작업을 진행했습니다.

---

## 2. 이번 주 목표는 실제 Docker 연결이었습니다

### 화면에 표시할 내용

1. Docker Engine 연결
2. 컨테이너 관리 기능 구현
3. 기존 화면을 React로 전환

**핵심 변화**  
정적인 화면 → 실제 컨테이너를 제어하는 관리 도구

### 발표 멘트

지난 단계에는 대시보드 화면의 형태만 있었습니다. 이번 주에는 Docker Engine의 실제 데이터를 가져오고, 웹 화면에서 컨테이너를 제어하는 것을 핵심 목표로 잡았습니다. 또한 이후 기능 확장이 편하도록 기존 화면을 React로 전환했습니다.

---

## 3. React와 Node.js가 Docker Engine을 연결합니다

### 화면에 표시할 내용

```text
사용자
  ↓
React 관리 화면
  ↓ HTTP API
Node.js 서버
  ↓ Docker Engine API
Docker Engine
  ↓
이미지 · 컨테이너
```

### 발표 멘트

사용자가 React 화면에서 작업을 요청하면 Node.js 서버가 요청을 받습니다. 서버는 Docker Engine API를 호출해 실제 컨테이너를 생성하거나 제어하고, 처리 결과와 상태 정보를 다시 React 화면에 전달합니다.

---

## 4. 컨테이너 핵심 관리 기능을 구현했습니다

### 화면에 표시할 내용

**조회**

- Docker Engine 실행 상태
- 이미지와 컨테이너 목록
- IP, 포트, 가동 시간
- CPU와 메모리 사용량

**제어**

- 컨테이너 생성
- 시작 · 중지 · 재시작
- 컨테이너 삭제
- 포트와 자원 제한 설정

### 발표 멘트

현재 대시보드에서는 Docker Engine의 실행 상태와 저장된 이미지, 전체 컨테이너를 조회할 수 있습니다. 컨테이너 생성부터 시작, 중지, 재시작, 삭제까지 기본 관리 기능을 구현했고 CPU와 메모리 사용량도 화면에서 확인할 수 있습니다.

---

## 5. 하나의 흐름으로 기능을 시연합니다

### 화면에 표시할 내용

1. Docker Engine 상태 확인
2. 저장된 이미지 목록 확인
3. Nginx 컨테이너 생성
4. 포트 `8080:80` 설정
5. 컨테이너 시작
6. `localhost:8080` 접속
7. 컨테이너 중지 및 삭제

### 발표 멘트

시연에서는 Nginx 이미지를 사용하겠습니다. 먼저 Docker Engine 상태와 이미지 목록을 확인한 뒤 Nginx 컨테이너를 생성합니다. 호스트 8080 포트와 컨테이너 80 포트를 연결하고 실행한 다음, 브라우저 접속으로 실제 서비스 동작을 확인하겠습니다.

## 6. OS 컨테이너가 바로 중지되는 원인을 확인했습니다

### 화면에 표시할 내용

**발생한 문제**  
Ubuntu·Arch Linux 컨테이너가 실행 직후 중지됨

**원인**  
컨테이너의 메인 프로세스가 종료되면 컨테이너도 함께 종료됨

**해결 계획**

- 컨테이너 생성 후 자동 시작
- OS 이미지에 유지 실행 명령 적용
- Nginx·Apache는 기본 서버 명령 사용

### 발표 멘트

Arch Linux 컨테이너가 생성 직후 중지되는 문제가 있었습니다. 확인 결과 컨테이너는 가상머신처럼 운영체제 자체가 계속 실행되는 구조가 아니라, 내부의 메인 프로세스가 유지되는 동안만 실행된다는 것을 알게 됐습니다. 다음 구현에서는 OS 이미지에 유지 명령을 지정하고 생성 후 자동으로 시작하도록 개선할 예정입니다.
